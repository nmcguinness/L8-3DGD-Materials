Part 1

How a GPU is organised

A GPU is many small cores, each with its own fast local storage, all sharing a large L2 cache and a wide connection to VRAM. Pixels are shaded in groups called waves (32 or 64 threads that run one instruction together). When a wave issues a texture sample, the request walks down the hierarchy until it finds the data.

An ALU instruction costs a few cycles. A trip to VRAM costs hundreds. The GPU hides that gap by switching to another wave while one waits, which only works if enough waves fit in the register file.

Part 2

How a texture is stored

Memory is a 1D sequence of bytes, so every 2D texture has to be flattened. Memory also moves in fixed blocks called cache lines. Here each texel is 4 bytes (RGBA8) and a line is 64 bytes, so one line holds 16 texels. Whatever layout is used, a fetch of one texel brings its 15 line-mates into the cache too.

Colours show which texels share a line. The path traces address order. Hover or tap a texel to see its address.

Part 3

How cache misses happen

A 16 × 16 block of screen pixels is shaded in Z-order, the way GPUs walk 2×2 quads through a tile. Each pixel samples a 64 × 64 texture. A sample hits if its line is already in L1, falls back to L2 if not, and goes to VRAM if neither has it. The caches use least-recently-used eviction.

Summary

What to take into your shaders

Keep neighbours together

Adjacent pixels should sample adjacent texels. Hardware tiling makes this work in any direction, but random or heavily distorted UVs defeat it.

Always mipmap minified textures

Without mips, a far-away surface skips across the texture and touches a new line for nearly every pixel. Mips keep the footprint close to 1:1.

Smaller texels, more hits

Compressed formats (BC1 to BC7) pack more texels into each 64-byte line, so every fetch brings in more useful data.

Leave room to hide latency

Misses are only slow if there is nothing else to run. Fewer registers per thread means more waves resident, and more waves to switch to.

Latencies, cache sizes and line sizes are illustrative values chosen to make the behaviour visible. Real GPUs use larger caches, set-associative placement, vendor-specific tiling, and texture compression, but the mechanisms are the same.
